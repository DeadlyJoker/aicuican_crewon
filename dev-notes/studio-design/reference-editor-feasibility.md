# 剪辑能力复用评估（2026-11-10）

## 当前决定

暂停扩写自制剪辑器。当前单轨式 Demo 不能代表专业剪辑能力：缺少完整多层画面、文本叠加、视频内嵌音轨识别与呈现、真实音画同步及媒体编码。已有项目与剪辑草稿保留，不迁移或覆盖。下一步只有在可复用编辑器通过真实媒体验证后才接入；尚未安装或执行完整第三方编辑器；后续已隔离验证 HyperFrames 0.9.30 播放器，范围见[播放器实测](reference-hyperframes-study.md)，不等于编辑器、多轨或导出通过。

文本属于画面合成层，应与视频、图片支持上下层叠加；配音、音乐和视频原声需要各自的音频控制。含原声的视频导入后必须明确显示有声状态，并支持静音、波形和分离音频；分离不能造成双重播放。仅增加几个轨道标题不能满足这些要求。

## 原站观察

rhTV 的“视频合成”“快捷剪辑”和左侧“剪辑”是不同入口。前两者创建画布节点，左侧剪辑进入独立全屏工作台；本轮实际观察到工作台 iframe 路径为 `/opencut/index.html`。路径和界面不足以确认其准确上游版本、修改范围或插件授权。原站测试使用自有研究画布，临时默认文本已撤销并重新打开确认空时间线；未执行生成或导出，研究节点保留。

Classic 源码审查固定于 `cf5e79e919144200294fb9fed22a222592a0aeea`，只读取官方源码，没有执行安装脚本。重点文件为 `apps/web/src/timeline/types.ts`、`timeline/audio-separation/index.ts`、`commands/timeline/element/toggle-source-audio-separation.ts`、`services/storage/types.ts`。`SceneTracks` 分为 `main`、`overlay[]` 和 `audio[]`；视频媒体保存 `hasAudio`，分离命令新增音频元素并关闭视频原声。这能证明存在实现基础，不能证明导入后默认显示独立音轨或波形，也不能代替运行验收。MIT 授权文本仍须随适用代码保留，依赖和附带素材需分别审查。

## 接入前的最小验证

使用带原声视频、第二层画面、字幕／文本和独立配音，验证多轨拖动、裁切、叠加、波形、静音和原声分离；实际播放与导出一段含这些元素的 MP4，确认音画同步。保存并重启后继续编辑，随后验证桌面 WebView 的媒体解码与文件访问。任一关键项失败则保持剪辑待接入状态，不继续用演示控件补成专业编辑器。

若验证通过，编辑器作为独立模块接入 Studio；DSH 插件负责项目入口、资产传递、任务与成品回传，编辑器负责时间线、播放、音画合成与导出。Agent 操作编辑器公开命令，不直接修改内部存储。既有 Demo 草稿保留独立版本，不能静默解释成第三方工程文件。

## 本轮 Demo 证据范围

已实现全屏工作台、独立编辑节点、版本引用、裁切字段和拖动手势；本地实际检查过片段移动、左右裁切、吸附、撤销／重做及部分刷新恢复。28 项局部模型检查通过。这些结果仅证明原型中的状态与交互，不证明真实视频播放、多轨或编码可用。停止扩写后，不干扰用户当前正在编辑的草稿。

## HyperFrames 后续核对

原站顶部 HyperFrames 已实际打开，确认是独立 Agent HTML 合成入口，与左侧 OpenCut 剪辑工作台区分。官方 HyperFrames 0.9.30 当前导出可嵌入播放器、时间线与编辑组件，并有独立 producer 渲染接口，值得优先验证；但本轮只有原站 UI、发布信息及固定源码核查，没有启动或渲染该引擎。新的产品分工、宿主职责、验证顺序及 Omniclip 后备候选见 [HyperFrames 研究](reference-hyperframes-study.md)。专业多轨验收要求不变，暂不以新按钮或若干空轨道替代真实编辑器。
