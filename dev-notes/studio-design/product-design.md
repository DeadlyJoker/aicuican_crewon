# CrewON Studio 产品设计

设计日期：2026-11-09。本文定义产品方向和样式原型的评审标准，当前处于产品设计阶段。原型中的项目、镜头、预算、生成状态和成片均为演示数据，不调用真实模型，不代表功能已交付。

## 产品定位

CrewON Studio 是 CrewON 生态中的作品创作工作室，围绕作品项目组织从目标表达、素材准备到制作和交付的完整过程。核心用户是希望低成本完成作品、但不熟悉提示词、模型和剪辑的普通创作者。首页提供一个目标输入，可附已有剧本、参考作品或其他材料；系统建议制作方案，经简短审阅后进入同一个无限画布继续完成作品。

文字、图像、视频、声音、剧本与分镜是项目内容和制作能力；短剧、镜头预演与互动故事可以成为按目标推荐的制作方案或项目工具。用户不必在开始时理解这些产品分类，也不必先选择一种制作模式。熟练用户可在项目内展开专业工具并精细编辑。

CrewON 提供身份、权限、专家、团队、工具、会话和自动化底座。Studio 提供完整的创作空间。项目、资产、任务和交付记录属于同一生态，用户从对话打开工作室时继续操作原项目。插件负责生态接入，独立界面负责制作体验；CLI 是 Agent 与自动化的调用入口。

产品衡量包括首次可用作品所需的操作次数与时间、每份采用结果的实际成本、局部修改导致的重做范围，以及项目重开后能否继续工作。首次完整出片、单镜头采用成本和修改后能否保留已有成果是当前重点；具体数值待真实用户与生成服务测试后确定，不先写成本承诺。

## 产品范围与设计基线

一级组织围绕作品项目：首页表达目标并继续已有项目，项目内查看方案、内容、任务与交付。主路径是“表达目标／导入内容 → 紧凑制作方案审阅 → 同一个无限画布”。方案负责说明会做什么，画布负责组织并编辑实际内容；内容工具按当前选择展开。

参考产品的“创作、云片场、短剧、互动影游”混合了泛称、制作空间、内容类型和叙事形式，只作为可吸收的功能与流程证据，不作为 Studio 已接受的一级导航。Studio 依据用户目标、成本和完整交付效果选择能力，参考站出现的能力不自动成为当前实施承诺。

图片节点可展开生成、参考编辑、局部重绘、抠图、扩图、增强、光影、多角度、角色三视图和图层拆分；视频节点可展开生成、参考约束、续写、重拍、增强、深度与动作相关能力；声音节点可展开旁白、配音、音乐和音轨处理。3D、空间、分支叙事等专业能力进入候选清单，具体纳入方式取决于对作品目标的帮助及完整验证。普通用户先看到当前步骤和必要选择，专业模型、CLI 和 API 参数放高级设置。

[rhTV 插件能力盘点](rhtv-capabilities.md) 区分客户端已暴露的接口、网页中观察到的入口，以及尚未验证的能力。静态工具数量与在线目录都只提供参考证据。Studio 继续保持 Agent 创作编排、可替换 API 执行、CrewON 生态共享，不依赖 RunningHub 作为业务底座。

| 优先级 | 本轮设计关注的结果 | 完整能力清单中的处理 |
| --- | --- | --- |
| 当前核心 | 普通用户从目标或已有内容完成一部可编辑、可预览、可交付的作品 | 先预览、复用资产、局部重做、费用确认、任务恢复和旧成果保留贯穿主路径 |
| 按项目需要展开 | 角色设定、镜头预演、图像处理、配音、字幕与剪辑 | 在相关内容或方案步骤中提供工具，不要求用户先选产品模式 |
| 候选专业扩展 | 3D／空间制作、互动故事、复杂编排与分发 | 保留参考与待设计事项；依据用户价值、成本与可验证的完整流程排序 |

样式原型用于评审目标输入、方案和画布；第二版评审路径见[原型评审](demo-v2-review.md)。设计以 DSH 主题、控件、圆角与字体规范为基础，视觉对齐和正式组件复用分别检查，差距见[DSH SOP 对照](dsh-sop-review.md)。正式实现复用共享表单、菜单、弹窗、提示和反馈，专业画布和时间线由 Studio 持有。嵌入 CrewON 时沿用宿主导航和 sidebar slot；独立 Studio 工作区也不另建账号、项目或插件状态。落地按 DSH 插件文档与生命周期执行，在产品设计评审前不把独立 HTML 原型搬成正式实现。

## 用户从哪里开始

| 用户已有内容 | 首次动作 | 系统给出的下一步 |
| --- | --- | --- |
| 一句话想法 | 直接描述想完成的作品，可附材料 | Agent 给出紧凑的制作方案，等待审阅 |
| 现成剧本或小说 | 导入文字，选择制作范围 | 展示拆分的剧集、场景和镜头，保留原文引用 |
| 人物、产品或场景图片 | 拖入画布，说明用途 | 建立可复用资产，建议相关镜头 |
| 参考视频 | 导入参考，说明保留和改变的内容 | 先解析镜头结构，再审阅复刻或转绘方案 |
| 已有 Studio 项目 | 从最近项目继续 | 恢复原画布、已采用版本、任务和最近成片 |

首页围绕“你想完成什么作品”保留一个输入区，附件、已有剧本和参考作品都是输入起点。最近项目展示封面、制作状态和最近交付，继续项目恢复原内容与位置。模板作为可选建议保存内容组织、素材需求和制作策略，用户无需先选模式或模板才能开始。

## 制作方案的紧凑审阅

首次制作方案只呈现作品目标、交付规格、将复用或补充的素材、简短制作步骤和费用范围。时长、画幅、角色等只在作品需要时出现；默认建议来自当前目标，用户可直接修改。主动作是确认方案并进入画布，需要修改时在同一份方案继续调整，不复制指令或另建一份内容。

费用确认绑定具体执行范围。低成本预览和已采用素材优先，无关镜头及资产继续复用；进入视频制作或扩大执行范围时，再说明新增用量与影响。没有可靠报价时说明用量和不确定部分，不把参考站的报价当硬预算保证。

已有项目直接继续，不重复创建制作计划。项目内的简单编辑围绕选中内容完成；影响下游结果或增加费用时才就近确认相关范围，不重新审阅整个项目。

## 工作室与无限画布

首页和项目工作室是两层空间。进入项目后，项目名、当前内容和制作状态提供持续的定位；短剧项目再展开剧集，切换剧集保留各自画布。画布、分镜和剪辑是同一个项目的不同观察方式，切换视图不生成另一份数据。

无限画布承载内容及其关系：故事简报、剧本、角色、场景、镜头、图像、视频、声音与成片。关系线表达“引用谁、由什么生成、采用到哪里”。它帮助用户理解作品构成，不要求普通用户先学习节点编排。

默认由 Agent 整理布局，并按剧集、场景和制作阶段分组。用户可以自由拖动、缩放、平移、连线、框选与分组，也能一键整理或适应视野。分组可折叠，复杂画布可搜索、定位，并通过小地图找回当前区域。撤销与重做覆盖可逆的画布和内容编辑；已产生的外部生成费用必须单独说明。

| 区域 | 常驻内容 | 逐步展开的内容 |
| --- | --- | --- |
| 顶部 | 项目与当前内容、保存状态、视图切换、预览和交付 | 剧集、项目设置、版本、共享权限 |
| 左侧 | 添加内容、项目资产、场景导航 | 素材分类、模板和高级节点 |
| 画布 | 视觉内容、简短标题、采用与运行状态、必要引用线 | 悬停操作、选中节点的编辑能力 |
| 右侧 | 当前选中图片、视频、声音或文本的属性与适用工具；未选中时为创作助手 | 提示词、模型、引用版本和任务详情 |
| 底部 | 当前缩放、定位与剪辑入口 | 可收起的镜头时间线、声音和字幕 |

卡片以画面为主，不堆放完整提示词和参数。选中节点显示固定位置的工具栏与内容属性，支持 Enter 进入编辑；打开属性区时保留所选内容的可见范围。节点的拖动区、选中态和操作按钮保持区分，避免移动内容时误触生成。小地图覆盖节点和当前视口的联合范围，内容移到负坐标后仍可定位。长弹窗的正文在内部滚动，底部主要动作保持可见。

## 分场剧本与制作输入

剧本工坊按场景组织镜头，允许编辑名称、故事概况、动作、对白和时长，并增删或调整场景与镜头。场景目录和画布分组来自当前剧本结构，不固定为两场。编辑先保留为草稿，关闭或刷新后可继续，应用前不改变画布节点与采用结果。

应用前审阅剧本文档与镜头的差异，只同步用户选中的制作输入。镜头输入与已保存值确有差异时作为未保存冲突项禁用；时长改回原值会清除对应草稿变更，不误阻塞。确有未保存对白等内容仍受保护，用户可以先保存剧本文档，保留这些输入继续处理。新增镜头在应用时创建一次，状态为尚未制作，不补造旧输出或候选 v1；从剧本或当前剪辑移出的内容保留原素材、候选与记录。

剧本旧版本只读保留原文与对白。复制剧本使用独立的场景、镜头与版本记录，副本应用不改写原剧本或原镜头。

剧本更新不等于重新生成。旧画面、时长、声音和采用快照继续可用，并标出需要复核的内容；用户可选择继续沿用，或为更新后的输入准备候选，再显式采用。画布、时间线和动态分镜使用实际采用结果；尚未采用结果的镜头不冒充已完成，交付入口提供定位待制作镜头或保存制作方案。

## 资产复用与版本影响

角色、场景、图片和声音在项目内保存为可复用资产，多个镜头引用同一资产，不重复复制。每项制作输入锁定资产 `sourceId`、采用结果 `candidateId` 和版本号（本地原型字段 `number`）；资产采用新版本只提示有更新可用，不自动改写镜头已锁定的参考或旧输出。

| 动作 | 改变的内容 | 保留的内容 |
| --- | --- | --- |
| 更新制作参考 | 下一次制作将使用的资产版本 | 已有候选和当前采用结果 |
| 准备候选 | 按准备时锁定的参考快照新增候选 | 制作参考与当前采用结果 |
| 采用候选 | 作品使用的输出版本 | 旧候选、输入草稿和其他镜头的参考 |

这三个动作分别操作，互不自动触发。候选展示其记录的来源版本；旧输出缺失来源信息时保持“未记录”，不使用当前连线或最新资产补写历史。

## 一条完整的制作故事

用户输入“做一条雨夜车站的温暖短片”。Studio 先收集风格、时长、画幅和预算上限。Agent 提出简短故事、角色与镜头方案，并说明将复用哪些素材。用户可以直接说“保留结尾，减少一个角色”，同一方案更新后继续审阅。

用户确认方案后，先制作成本较低的角色参考与镜头预览。角色一旦采用，后续镜头引用同一版本。用户对预览说“第二镜头改成近景”，系统展示受影响的镜头与预计追加用量；无关镜头保持可用。用户确认后才进入视频和配音执行。

生成完成后，系统建议镜头顺序、节奏、声音与字幕。用户可在画布选中镜头，在底部时间线调整顺序、入出点、对白和字幕。预览结果通过后导出，交付记录保留当次采用的全部输入。用户之后修改结尾、切换设备或重开项目，仍可继续编辑，并查看旧成片。

## 成本、采用与恢复

预算分成方案、预览、视频与配音、重做和导出几个可理解的阶段。执行前显示可核实的用量估算、估价依据和不确定部分。没有配置单价时显示用量，不显示虚假的精确金额。项目预算约束累计用量与自动重试，超出已批准范围必须停下，让用户确认新的执行范围。

编辑输入、候选结果和已采用结果分别保留。候选保存生成时的内容快照，点开或切换比较不会改变采用；用户明确采用后，画布、时间线与动态分镜才使用对应快照，包括画面、时长和对白。未提交的编辑输入继续保留，不能因查看或采用候选而被回填覆盖。

单项内容准备新候选时保留当前采用结果，只在该项候选区追加结果，不新建画布节点，也不重新审批整个项目。项目记录显示实际发生的本地输入编辑、候选新增和采用；画布移动与撤销单独管理，不删除作品记录。剧本更新的复核规则见[分场剧本与制作输入](#分场剧本与制作输入)，参考素材的锁定与更新规则见[资产复用与版本影响](#资产复用与版本影响)。复用资产、缓存可用结果和先审预览共同降低试错成本。

任务有排队、执行、可预览、失败和状态未知等明确状态。网络中断后，先恢复原任务并查询；状态未知时不自动重复提交。重做和重新查询是两个独立动作。错误报告说明受影响的镜头、已有结果是否保留以及安全的下一步。恢复项目时保留已保存的画布布局、内容版本、采用结果、时间线与导出历史。

## Agent 与 API 的职责

Agent 负责理解目标、编剧、角色设定、镜头设计、提示词、制作方案、执行编排和质量审阅，所有创作结果进入可查看的项目版本。用户可以替换生态内的专家，并在轨迹中查看其实际执行过程。

图像、视频、配音和渲染 API 负责执行明确的结构化请求。媒体服务设置集中在高级配置，普通用户选择可理解的效果与成本档位。项目仍保存实际使用的模型、执行参数和版本，以便追溯、更换服务和恢复任务。API 不成为项目、画布或资产的所有者。

## 样式 Demo 的使用验收

样式评审沿“目标或已有内容 → 紧凑方案审阅 → 同一个无限画布”检查完整路径，具体要求见[第二版原型评审](demo-v2-review.md)。图片、视频、声音和文本属性与适用工具分别匹配；先预览、复用、局部重做和费用确认保持可见且易理解。参考站的四模式不作为首页必备标签；尚未验证的专业编辑、执行与交付明确保留设计范围。

本轮原型已在本地 Web 验证候选比较与显式采用、输入草稿保留、项目隔离和作品记录，以及剧本冲突项保护、分场草稿刷新恢复、双击应用仅新增一次、未制作镜头提示、采用后预览更新、旧版本只读、副本独立、等值时长草稿清除、桌面与移动端工坊布局、场景切换和折叠输入保留，以及分场重排不改实际剪辑时间。具体观察及未完成检查见[第二版原型评审](demo-v2-review.md#本轮原型验证记录)，不延伸为正式插件、真实 API、App 或插件构建验收。

页面须持续标明“交互原型／演示数据”。生成、预算和交付反馈均为可交互状态演示；不得出现让用户误认为真实模型或真实扣费已执行的提示。样式评审通过后，另行确认功能范围、真实服务、质量标准和落地顺序，再进入产品开发。

资产复用与版本影响目前完成本地数据模型及候选状态联跑检查，相关浏览器使用路径另行验收。
