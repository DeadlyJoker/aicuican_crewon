# CrewON Studio 第二版产品原型评审

设计日期：2026-11-09。本文是第二版样式原型的产品参考，定义评审路径和可理解的能力分类，不说明正式 DSH 插件已经交付。实际交互与布局以本轮浏览器截图和检查为准，媒体生成、计费、授权和导出仍各有独立验收范围。

## 评审目标

首页围绕作品项目提供一个目标输入，用户可附已有剧本、参考作品或其他素材。主路径是“表达目标／导入内容 → 紧凑制作方案审阅 → 同一个无限画布”。系统按目标建议制作过程，用户不需要在开始前选择创作模式或理解媒体技术分类。核心评审结果是普通用户能以较少决策和可理解的费用完成作品。

短剧、镜头预演和互动故事可作为推荐方案或项目中的工具；图片、视频、声音、剧本等是项目内容与辅助能力，按当前内容展开。参考产品观察与本产品取舍分别说明，来源见[产品设计](product-design.md)和[rhTV 能力盘点](rhtv-capabilities.md)。

## 交互收敛修订

用户反馈当前界面仍不够简洁后，按参考页实际操作制定了[画布交互收敛](interaction-simplification.md)。下一版以该规则调整单击选择、就地操作和完整编辑的呈现层级；下文已有界面与验证记录保留为当前原型事实，不作为该修订已实现的证据。

## 信息架构分层

| 层级 | 负责的问题 | 可见内容 |
| --- | --- | --- |
| 产品生态 | 我在哪里、和 CrewON 如何衔接 | CrewON Studio 品牌、项目、资产及生态能力入口 |
| 作品项目 | 新做什么、继续哪份内容 | 目标输入、已有材料、最近项目与交付记录 |
| 制作方案 | 如何完成目标、先确认什么 | 作品目标、交付规格、素材复用、制作步骤与用量说明 |
| 内容编辑 | 当前编辑什么、引用什么 | 同一个无限画布及按需打开的专业编辑视图 |
| 内容工具 | 对当前内容做什么 | 生成、编辑、参考约束、光影、构图、配音、增强等上下文能力 |
| 执行设置 | 如何执行、将使用多少资源 | 专家、实际模型、可替换 API、参数、任务与恢复信息 |

参考站的创作、云片场、短剧、互动影游分别混合了泛称、制作空间、内容类型和叙事形式，不直接照搬为 Studio 并列一级导航。媒体目录和 45 项图片配方也不决定首页组织；能力范围保留评估，实际呈现按当前作品目标与优先级取舍。

## 首页与首次进入

首页保留一个目标输入，附件、已有剧本与参考作品作为就近的输入起点。用户补充材料时保留已输入文字；系统只收集当前制作不可缺少的信息。最近项目直接继续原内容和位置，新建动作建立明确的新草稿，不把“开始创作”默认为打开旧短剧示例。

| 用户带来的内容 | 首页动作 | 第一份方案说明 |
| --- | --- | --- |
| 一句话目标 | 描述想完成的作品 | 建议的作品结构、素材需求和制作步骤 |
| 已有剧本 | 上传或粘贴正文，说明想保留的内容 | 使用已有文本的范围、可调整部分及制作组织 |
| 参考作品 | 添加图像或视频，说明参考哪些内容 | 参考内容如何使用、哪些部分保留或重新制作 |
| 已有项目 | 点击继续 | 直接恢复原工作区；新增执行只审阅相关范围 |

短剧、镜头预演或互动故事可以出现在推荐方案中，解释它为何适合当前目标。用户可以修改建议，不需要先在首页理解并选择这几种分类。未完成设计的能力不自动跳到旧示例或通用空白画布并声称可用。

## 方案审阅与进入画布

方案卡保持紧凑：作品目标、交付规格、将复用的素材与需要补充的内容、简短制作步骤、当前阶段用量和费用不确定性。角色、时长、画幅或分支数量只在相关作品中出现。普通用户先看到建议结果与下一步，模型和参数放高级设置。

主动作表达“确认方案并进入画布”；修改继续作用于同一方案。确认费用绑定实际执行范围，不把浏览器打开画布或演示动画写成已经调用媒体服务。参考站的四种创建页仅作为取舍依据，详细观察见[参考产品模式观察与取舍](product-design.md#参考产品模式观察与取舍)。其入口和配置已只读查看，生成、收费、项目修改及完整交付没有由该观察验证。

先使用低成本预览和已采用素材，再决定是否制作视频或扩大执行。局部修改只确认受影响的内容与追加用量，其他成果保持可用；已有项目继续时不重新创建或审批整份计划。任务未知时查询原请求，不用新任务掩盖状态。

## 一个画布，多种内容

项目画布保留内容、素材引用和结果采用关系。图片可以成为视频参考，声音可以用于成片，单独制作的角色资产也可在短剧中复用。跨类型操作创建新的相关内容，并保留来源；不把原图片直接改写成另一种节点，也不因此丢失旧候选。

| 当前选择 | 右侧首先展示 | 就近的常用动作 | 更多工具中的内容 |
| --- | --- | --- | --- |
| 未选中 | 创作目标、当前项目状态、创作助手 | 添加内容、引用素材、继续未完成任务 | 项目设置、能力总览 |
| 图片或角色／场景图 | 图片预览、创作描述、参考、采用版本 | 参考编辑、更清晰、调整构图、生成相关画面 | 布光、表情、多角度、三视图、拆层、空间推演 |
| 视频 | 预览、时长、输入参考、候选和任务状态 | 调整视频、续写、增强、换参考 | 片段重拍、动作相关处理、深度与空间生成 |
| 声音 | 文案或用途、音色／风格、时长、候选 | 调整文案、试听、重新制作、采用 | 音乐续写、音轨提取及其他实际支持的处理 |
| 剧本或分镜 | 正文／镜头内容、角色场景引用、修改影响 | 修改内容、生成分镜、定位相关素材 | 角色设定、结构调整、批量制作范围 |
| 多选或分组 | 已选内容和共同状态 | 对齐、分组、复制、批量确认范围 | 共同兼容的制作工具；不兼容动作保持明确不可用 |

卡片保持画面或内容预览、短标题和状态，不常驻完整提示词、模型列表和所有工具按钮。悬停操作同时提供键盘与触摸可达入口。右侧查看内容与执行前确认使用一致的信息顺序：目标、输入、将产生的结果、影响范围与用量。

## 候选、输入与采用

当前原型的候选交互由 `candidate-ux.js` 与 `candidate-ux.css` 承载，候选保存固定快照。候选区和比较弹窗分别标出当前采用与正在比较的内容；切换 v1、v2、v3 或关闭比较，只查看结果。只有点击明确的“采用”动作，作品所用结果才改变。

| 内容 | 当前原型行为 |
| --- | --- |
| 编辑输入 | 未提交的描述、时长和对白保留在草稿；保存输入不改写采用结果 |
| 候选快照 | 为单项内容追加固定结果，不增加画布节点，不走整项目审批；新增前显示作用范围并校验描述 |
| 当前采用 | 画布、时间线和动态分镜读取采用快照，查看其他候选不改变它；显式采用后再更新画面、时长与对白 |
| 项目记录 | 展示实际发生的本地输入编辑、候选新增与采用；节点移动和布局撤销使用独立记录 |

这些是本地示例内容管理，不表示已执行媒体生成。原示例和新的创作草稿分别保留；重新体验不会覆盖旧项目。选中内容的 36px 工具按钮、Enter 编辑与自动平移帮助用户保持操作位置，小地图把节点和视口一起纳入定位范围，支持负坐标。长比较弹窗正文滚动，主要动作固定在底部。

## 剧本草稿与画布同步

当前原型的分场工坊、变更审阅和动态画布由 `script-workbench`、`script-impact.js` 与 `script-canvas` 承载。名称、故事概况、场景和镜头先进入独立草稿，应用前不改写作品节点。分场目录与画布根据当前剧本结构生成，不固定为两场。

审阅列出更新制作输入、新增镜头和移出当前剪辑的范围，由用户选中需要同步的项目。镜头已有未保存输入时，该项禁用并说明冲突，应用剧本文档不覆盖旧草稿。旧采用结果和候选继续保留，更新输入的内容提示待复核，允许继续沿用。移出当前剪辑保留素材，新镜头在得到并明确采用候选前保持尚未制作，不能生成虚假的 v1 或成片状态。

## 图片快捷工具的组织

rhTV 当前账号目录返回 45 个图片快捷场景。它们主要是处理配方，不需要在首页或每张节点上平铺 45 个按钮。Studio 可用下面的用户语言组织“更多图片工具”，搜索匹配操作名及作用；实际开放按提供方能力和质量检查决定。

| 分组 | 已观察到的场景 | 交互重点 |
| --- | --- | --- |
| 分镜与机位 | 多机位九宫格、剧情推演四宫格、25 宫格连贯分镜 | 先展示宫格形式及处理范围，再确认是否替换当前候选 |
| 光影 | 主光、辅光、轮廓光、发丝光及其他布光配方 | 展示预期方向，默认保留原采用版本 |
| 角色 | 三视图 | 要求合适的角色参考，说明输出是一组角色设定图 |
| 前后画面 | 3 秒后、5 秒前 | 说明这是相关静态画面推演，不是已生成连续视频 |
| 构图与运镜推演 | 推、拉、摇、移、跟、固定、环拍、弧线运动 | 图片上下文称构图推演；视频运动需要独立视频请求 |
| 表情 | 微笑、思考、疑惑、哭泣等 | 先判断素材是否适用，不能对任意场景强推人像动作 |
| 空间与环境 | 深度视差、雨雪、沙尘、丁达尔、余烬、荧光效果 | 展示新候选的位置与原结果保留方式 |

默认露出的常用动作随内容变化，数量保持少量；完整目录放在可搜索的工具浮层中。工具名不可暗示尚未验证的质量保证，例如“一键人物完全一致”。

## 专业空间与交付

画板、角色造型、镜头预演、3D 导演台、空间生成、声音编辑、剪辑与字幕分别保留专业编辑入口，按当前内容打开并能回到原画布位置。3D／空间模型目录不等同可交互的 3D 导演台；rhTV 的视频正片生成操作不等同整集剪辑导出。时间线、裁切、混音、字幕和编码交付需要 Studio 自己的完整设计。

模板是可修改的制作结构，由创作助手按作品目标推荐；普通用户不必先选择模板或搭节点图。镜头预演、互动故事和 3D／空间制作作为专业能力评估，不因参考站有入口就提升为一级产品。分享、社区和模板分发按实际用户价值另行排序，后续完整编辑、运行与交付仍待设计和验证。

## 能力范围与实际优先级

| 优先级 | 原型需要解释的用户价值 | 进入路径 |
| --- | --- | --- |
| 当前核心 | 从目标或已有内容完整出片，少量关键决策、费用明确、结果可修改 | 首页 → 方案审阅 → 画布 → 预览与交付 |
| 当前步骤需要 | 角色、分镜、图片处理、声音、字幕、剪辑，以及局部重做 | 在方案步骤或选中内容旁展开 |
| 候选专业扩展 | 镜头预演、3D／空间、互动故事、复杂编排与分发 | 根据目标推荐，具体流程和价值单独评审 |

能力清单用于避免遗漏可评估的手段，优先级用于决定本轮用户必须看到和能够完成的路径，两者分开呈现。没有进入核心路径的能力仍可研究，但不挤占普通用户第一次创作的主要操作。

## 本轮原型验证记录

本轮已在本地 Web 用示例数据检查以下路径；结果只覆盖当前原型交互。正式插件、真实 Agent／媒体 API、App、实际计费和成片编码均未由这些检查验收。

| 检查 | 实际观察 |
| --- | --- |
| 比较与采用 | v1—v3 切换不改变当前采用；明确采用 v2 后，所选镜头由 8 秒变为 6 秒，项目总长由 30 秒变为 28 秒 |
| 输入草稿 | 比较及采用后，尚未提交的 10 秒输入和对白仍保留；刷新后恢复 |
| 项目隔离 | 进入并修改新草稿后，原示例项目仍保持原内容 |
| 项目记录与撤销 | 项目记录为 5 条时，移动节点并撤销，记录仍为 5 条 |
| 390px 比较弹窗 | 正文无水平滚动，底部动作在视口内 |
| 空描述键盘提交 | 用 Space 激活提交后显示校验，不新增候选 |

本轮剧本联动另用两个本地草稿完成下列检查；示例帧编号和节点数用于限定观察范围，不证明真实生成。

| 剧本联动检查 | 实际观察 |
| --- | --- |
| 未保存输入冲突 | 草稿 7 的镜头 2 有未保存的 10 秒输入和对白，变更审阅中该项禁用；只应用剧本文档后，未保存字段及采用 frame4 保留 |
| 分场草稿恢复 | 草稿 8 修改标题、概况、镜头 2 动作对白与 8→6 秒，新增第三场便利店门口及一个镜头；立即刷新重开，草稿内容都在，应用前画布仍为 8 节点 |
| 双击应用 | 浏览器原生双击应用后仅到剧本 v2、画布 9 节点，只新增一个镜头；旧镜头仍为 frame3／8 秒，新镜头显示尚未制作且无假 v1 |
| 未制作镜头交付 | 导出先提供待制作镜头定位及下载方案，没有显示虚假的成片完成 |
| 候选与剪辑 | 查看首个候选后仍待制作，明确采用 v1 才加入；旧镜头更新候选并采用 v2 后，时间线为 5 镜头、34 秒 |
| 动态分镜对白 | 最后对白“这盏灯，也借你一程。”来自新采用候选，未继续使用旧输入或固定文案 |

剧本联动的补充 UI 检查结果如下，相关状态逻辑另由独立 VM 调用真实输入监听复核通过；这不扩大为正式插件或真实服务验收。

| 补充检查 | 实际观察 |
| --- | --- |
| 旧版本只读 | 打开旧剧本 v1，仍保留原对白，只读查看不改当前版本 |
| 复制独立性 | 副本使用独立 scene／shot ID 和 v1／v2；应用副本新增 4 镜头，原剧本文字与原镜头不变 |
| 等值草稿清除 | UI 时长从 8→6→8 后对应草稿变更清除，不误阻塞审阅；真实未保存对白仍作为冲突项阻塞 |

桌面与移动端工坊补充检查已完成，均为当前原型的真实浏览器观察。

| 布局与操作 | 实际观察 |
| --- | --- |
| 1280×720 工坊 | 弹窗 y=24、高 672，正文可视高 527 且可内部滚动，底部操作的下沿为 696，始终在视口内 |

| 分场重排 | 重排两场且未勾选同步剪辑时，画布仍显示实际剪辑范围：街口 16—30 秒、站台 0—16 秒 |

参考站的工作台观察与 API 查询限度见[rhTV 盘点](rhtv-capabilities.md#剧本工作台与查询限度)；它们不作为本地脚本联动已经适配参考接口的证据。
