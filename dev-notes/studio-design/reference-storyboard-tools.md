## 后续实现需要保留的区别

11个一级入口中有7个直接项目，以及光影校正、运镜控制、情绪重塑、动态场效4组子菜单，共38个子项；按可见菜单统计共45个叶子入口。此数量只是界面目录，不证明它们使用45种不同模型或执行服务。

分镜大师中的“电影级光影校正”是16项具名选择；工具栏独立的“打光”入口则打开球体、主光源方向、水平环绕、高度、强度、颜色面板。两种界面已分别打开核实；不能只实现后者就宣称覆盖前者，也不能未经验证假定两者的执行效果相同。

“情绪重塑”是8项离散入口，不能直接等同于人物调节中的情绪、视线或嘴巴参数。“运镜控制”在图片节点分镜菜单内出现，尚未执行验证，因此不能据名称断言一定输出视频。雨雪等动态场效同理，输出类型、任务形式、取消行为、费用和结果版本均待验证。

## Demo 菜单验收

目录数据集中在 reference-storyboard-catalog.js，工具草稿与工具栏共用同一份名称；子项保存为“组名 · 子项”，避免后续同名选项冲突。菜单展开不提交任务，选择后打开独立草稿，不覆盖普通提示词。示例提交继续走既有候选输入快照；真实服务未接入。

子菜单移到 body，避免画布变换、节点图层和父菜单滚动裁切。右侧不足向左展开，窗口上下保持边距，长菜单内部滚动。鼠标经过父项展开；键盘右键进入、左键返回、Escape逐级关闭、上下及首尾键移动，Tab退出菜单；父菜单滚动、窗口变化和重绘清理子菜单。

## 原生接口核对（2026-11-11）

浏览器控制中断期间，通过已安装的 rhTV 0.7.1 客户端只读查询当前账号的国际站目录。精确命令为 `rhtvcli image shortcut list`；该目录不接受本轮尝试的 `--canvas-id` 参数，帮助虽列为通用选项，本轮带该参数实际返回 INVALID_ARGUMENT，移除后成功。不调整环境或账号，不运行工具。结构化证据保存于 [图片快捷目录快照](assets/reference-study/image-shortcuts-20261111.json)，模型列表去重存放但每项保留对应关系；这是当前账号可见目录，不能推为所有账号或未来版本全集。

本地45个叶子名称与接口45项逐项比对一致，没有缺项或额外项。接口提供的执行准备信息比菜单名称更明确：

| 接口字段 | 当前证据 | 对 CrewON 后续执行设计的影响 |
| --- | --- | --- |
| nodeType | image | 当前快捷目录属于图片工具；运镜、动态场效等名称不等于视频输出承诺 |
| mode=IN_PLACE | 多机位九宫格、剧情推演四宫格、25宫格连贯分镜，共3项 | 对原图片节点准备新版本；已有采用结果和历史继续保留，不能覆盖历史文件 |
| mode=CREATE_RIGHT | 其余42项 | 准备右侧派生图片节点，并固定当前引用版本；不能所有入口都更新同一个源节点 |
| gridType | 上述3项分别为9、4、25，其余为null | 宫格布局与光影、情绪等独立效果分开建模 |
| requiredInputs | 全部为image | 无已采用图片时不能发起真实执行；仅有文字描述不满足这一目录的输入条件 |
| defaultModel | 全部为null | 不从模型列表首项推定默认付费模型，须用户或项目明确配置 |
| modelCodes | 同一组16个当前可见图生图模型 | 45个快捷入口不等于45个模型；真实接入前仍需读取所选模型schema |
| paramsLocked | 全部包含resolution | 接入原生快捷协议时按其约束处理，不能直接提交普通参数表的所有字段 |

这些字段只证明接口的准备模式，不是已执行结果：尚未验证实际生成、价格、取消、失败恢复及新候选回传。本轮没有将 `IN_PLACE` 解释成删除旧版本，也没有因 `CREATE_RIGHT` 就在原站建节点。Demo当前保留独立工具草稿与明确的本地示例状态；真实适配应按以上两种模式分别处理，不能继续把所有入口视为同一种候选提交。该目录只用于理解参考产品，CrewON的执行仍应与外部平台解耦，由自己的Agent编排与已配置API执行。

另只读核对参考画布capabilities：高级graphActions支持text、image、video、audio、script及CAS提交，旧commandTypes层的createNodeTypes仅列rh-text，两层不能混用。该响应没有公开全景4／12视角相机分布或透视曲度算法，不能据此补猜测实现；也不能以未列出为理由认定网页没有这些能力。
