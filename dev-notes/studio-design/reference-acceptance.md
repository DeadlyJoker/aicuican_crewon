# rhTV 对照验收总览

核对日期：2026-11-11。目标仍为完整理解 rhTV 的入口、短剧工作台和无限画布，再据此打磨 CrewON Studio；本表不把已经实现的部分重新定义为完整目标。当前交付物是静态交互 Demo，不是已安装的 DSH 插件，也不是可实际生成整集的制作系统。

## 状态如何理解

“本地实测”只覆盖该行写明的路径；“示例”指不运行 Agent 或媒体生成；“待核实”指缺少原站实际行为证据；“未实现”指当前不能使用。源站页面、API目录、模型测试和截图分别提供不同证据，不能互相代替。详细时间记录见[差异审计](reference-fidelity-audit.md)。

## 产品主路径

| 领域 | 已有证据与本地行为 | 尚未证明或缺少的能力 |
| --- | --- | --- |

| 分镜视频草稿 | 按组生成空视频草稿、固定已采用参考、列出待补素材、定位资产并返回；减少重复提示词；阅读页汇总当前引用资产与版本、缺图状态；刷新及旧版本保留 | 真正生成视频；当前只是待制作输入与引用，不是播放结果 |

| 节点列表 | 媒体分类、搜索、标签、定位同一节点；本机视频实际解码首帧、静音暂停、搜索刷新恢复 | 原站当前视频分类为0，不能宣称视频列表行为完全对等；右键未看到额外菜单 |

## 后续顺序

1. 继续核实原站专业编辑的实际界面与提交语义：导演台需先收到当前待答问题的许可；标注／裁剪需要可观察的可用入口；全景批量与导入不能仅从按钮名推断。
2. 对已接入的主路径做桌面输入和长内容回归，优先处理数据错配、误提交、浮层遮挡、状态丢失；不以不断添加菜单代替这些检查。
3. 专业剪辑按已确认的开源引擎验证条件推进；真实服务和正式DSH插件另作完整实施验收，不将当前样式Demo宣称为全流程产品。
