# 团队使用逻辑

本文区分已落实的展示与正确性调整，以及仍需实现的编排能力。

## 对象与入口

| 对象 | 保存什么 | 打开时做什么 |
| --- | --- | --- |
| 办公室 | 长期成员、职责、成员身份 | 打开大厅，继续日常讨论 |
| 项目 | 一个持续目标及其话题 | 查看该项目的话题，不触发执行 |
| 话题 | 一个具体问题的消息及成员回复 | 恢复该话题，确认当前用户已读 |
| 工作流模板 | 节点、依赖、Agent 预设 | 查看或编辑下一次运行的配置 |
| 工作流运行 | 本次输入、冻结的配置、执行与审批状态 | 恢复本次运行，不重新派发 |

“打开大厅”沿用已有办公室对话，不创建项目。新项目只从项目入口创建。大厅里的临时讨论保持在大厅，用户需要归档为项目工作时再明确创建项目与话题。

## 页面职责

团队页负责创建和配置办公室、成员与工作流，并按项目组织讨论。对话页承载用户输入和成员输出。顶部的“查看办公室”“查看工作流”在原生右侧栏显示与当前会话绑定的详情，办公室设置和工作流编辑直接在当前对话弹窗中操作，所属项目入口仍按当前对象 ID 定位项目页。运行历史在当前页浮层中分页浏览，展开输入和结果时保留原对话与侧栏位置。工作流详情读取本次运行的配置快照。完整模型与工具记录继续由原生“轨迹”承载。

办公室对话保留用户输入、成员回复及需要用户处理的异常，隐藏主助手的欢迎、结果转述和内部完成回执。审批等需要用户行动的卡片保留。大厅没有选定成员时，引导用户通过 @ 选择成员，避免请求交给一个不可见的默认助手。

## 调度规则与组长

办公室可指定已有成员为组长，设置保存在办公室定义中。普通问题由组长接收，定向 @ 交给指定成员。清除组长后，输入框要求显式选择成员。切换组长沿用各成员现有身份与会话。

组长通过 `office_delegate` 把具体任务交给当前办公室的固定成员，等待真实结果后汇总。委派工具验证当前组长、办公室、话题与目标成员，沿用成员派发记录和原生轨迹。成员成果显示在同一对话，组长生成的子任务标明派工身份。委派重复调用按执行身份去重，跨办公室派工和自我委派被拒绝。

## 用户故事与验收

| 用户意图 | 预期路径 | 必须避免 |
| --- | --- | --- |
| 临时问一位同事 | 打开大厅 → @ 成员 → 收到具名回复 | 自动创建项目，或额外转述结果 |
| 建立长期工作 | 创建项目 → 新建话题 → 指定通知成员 | 把新问题接到不相关的旧话题 |
| 继续昨天的问题 | 打开原项目、原话题 → 继续回复 | 打开详情时再次执行任务 |
| 查看未读 | Inbox → 对应话题 | 查看某成员 Inbox 就替该成员确认已读 |
| 消息投递失败 | 保留请求和失败状态，成员 Inbox 保持未读 | 尚未送达就清空未读 |
| 执行中有新消息 | 只确认本次确实投递的消息水位 | 把新消息当成成员已看见 |
| 成员结果基于旧上下文 | 保留结果并提示话题回填冲突 | 静默丢弃结果或绕过版本校验 |
| 同一流程换输入 | 由模板发起新运行 | 覆盖以前的输入、配置或审批 |
| 查看旧工作流 | 打开旧运行及其冻结步骤 | 展示最近编辑的模板冒充旧配置 |
| 重启后继续 | 恢复身份、话题、未读和运行状态 | 自动重发已接收任务 |

## 话题与成员会话

项目列表和 Inbox 直接打开话题主对话，团队管理页保留项目与话题导航。话题对话统一显示完整账本时间线，旧大厅和当前话题产生的消息按同一顺序呈现。待完成的原生投递跟随来源消息展示，结果写入账本后替换待完成状态，按消息身份去重。可见时间线单独确认已读。右侧详情跟随当前话题，展示所属项目和成员。

长期角色身份与执行会话分层。每个话题为成员分配独立原生 Session，同一话题继续保留上下文，不同话题并行隔离。大厅原有成员 Session 与旧记录继续保留。默认共享成员职责和 Agent 预设，跨话题知识共享需要单独定义。

话题绑定、执行子会话 ID 和消息归属持久化到 SQLite。重复打开恢复同一对话，重启后保留成员上下文，重复请求按原身份处理。首次进入通过零模型初始化轮次使话题成为正式会话。
